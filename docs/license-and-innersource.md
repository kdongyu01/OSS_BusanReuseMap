# 라이선스 비교와 Inner Source 로드맵

## 라이선스 비교

| 라이선스 | 핵심 조건 | 이 프로젝트 적용 판단 |
|---|---|---|
| MIT | 저작권·허가 고지 유지, 책임 부인 | 단일 개발자 MVP의 간단한 코드 공개에 적합 |
| Apache-2.0 | 고지 유지, 특허 조항과 NOTICE 고려 | 특허 보호가 중요한 조직 배포에 적합 |
| GPL-3.0 | 파생 배포 시 동일 라이선스 공개 요구 | 서비스 코드의 결합·배포 자유를 제한할 수 있어 초기 MVP에는 신중히 검토 |

현재 코드는 MIT를 선택했습니다. 공개 데이터와 기업 데이터는 코드 라이선스와 별도로 출처·이용 조건을 확인합니다.

## Inner Source 로드맵

1. **준비:** README, CONTRIBUTING, CODE_OF_CONDUCT, Issue 템플릿과 리뷰 가이드를 표준화합니다.
2. **시범:** 공개 가능한 합성 데이터와 작은 기능 Issue를 대상으로 내부 구성원이 PR을 제안합니다.
3. **품질:** CODEOWNERS, 브랜치 보호, CI 필수 통과, ADR 검토를 적용합니다.
4. **확장:** 재사용 가능한 Composite Action과 패키지를 사내 저장소에 공유합니다.
5. **측정:** PR 응답시간, Cycle Time, 재사용 Workflow 수와 기여자 수를 분기별로 검토합니다.

실제 기업 기밀과 개인정보는 공개 저장소에 포함하지 않으며, 내부 전환 시 접근권한과 데이터 분류를 별도로 승인받습니다.
